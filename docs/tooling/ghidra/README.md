# Ghidra and the MN103 module

Ghidra is a free disassembler and decompiler. It has no built-in support for the
MN103 CPU that runs most Olympus camera code. An independent Ghidra processor
module for MN103 / AM33 / AM33-2, with decompiler support, is published at
[nsud-dev/ghidra-mn103](https://github.com/nsud-dev/ghidra-mn103) (GPL-3.0-or-later).
It is a separate project; nothing from it is vendored here. It is an alternative
to the [IDA 4.9 route](../ida/README.md), and like IDA it is optional for the
probes and builds in this repository.

Language id `MN103:LE:32:AM33-2`. Tested with Ghidra 11.4.2 (Java 21).

## How the module was derived

- The SLEIGH specification is generated from the binutils 2.42 opcode table
  (`opcodes/m10300-opc.c`) and follows binutils' instruction-length and
  first-match rules. That derivation is why the module is GPL-licensed.
- Instruction semantics follow the GDB 15.1 MN10300 simulator.
- On MN103, the `call` instruction itself saves the callee's registers and
  allocates the callee's stack frame. The module passes that information to the
  callee's entry, so stack locals and stack arguments decompile correctly. A
  script (`MN103FixCallFrames`) sets it at every call target after analysis.
- `setlb`/`Lcc` hardware loops (a loop start register and a conditional branch
  back to it) are tracked through the code, so they decompile as ordinary loops.

## Reported checks

These were run by the module's author on E-M5 III build 1700 main
(decoded SHA-256 `4097f57751ac30c24589448865b2824891a754744eae63ab14359fd46c1cf4be`)
and have not been re-run here:

| Check | Reported result |
| --- | --- |
| Length, mnemonic and operands at every position `objdump -D -m am33-2` decodes in the main | 14,086,364 of 14,086,364 identical |
| Same on 5 MB of generated byte patterns | 3,164,334 of 3,164,334 identical |
| 4,489 single instructions run in the GDB simulator and in Ghidra's p-code emulator; registers, flags, mdr, sp and memory compared | 4,250 agree; the 239 differences are attributed to simulator defects (sat16 signedness, swhw_add, asr carry, addc/subc flags, one divide by zero) |

Limits stated by the author: the `udf00`/`udf01` user-defined operations are
modeled as 32-bit multiplication from their use in this firmware, not from
documentation; DSP accumulator operations are pseudo-ops; divide by zero and the
FPU operations were not checked against the simulator. The calling convention
used for parameters (d0, d1, a0, a1, then stack) is read from the code.

## Verification and limits

The module's repository includes the generator and the validation scripts, so
the decode comparison can be re-run against any main image with GNU objdump.
Like [IDA](../ida/README.md) and GNU disassembly, the module is not proof on its
own. Confirm instruction boundaries and the input hash before relying on a
decompiled function.
