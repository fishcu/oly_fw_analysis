# Reading the OM-3 decompilation

The latest local continuation is in
[the stage-0 verification record](HARDWARE-STAGE0-RECORD.md#completed-verification)
(updated 9 November): task-context mutex repair, 28/28 profile edges, native
context refusal, and native section-loading/diff checks. These remain offline
results under documented fixtures; no installable image exists.

For the current independent AF-button profile investigation, read the
[feature specification and findings](analysis/button-af/FEATURE-SPEC.md#current-evidence-and-limits)
and its linked evidence manifests. Updated 7 November 2026: the research
prototype is not ready for installation; no camera has been flashed.
The later gate-closure review, its probe index and the AF request-path findings
are in [AF-GAP-CLOSURE-ASSESSMENT.md](AF-GAP-CLOSURE-ASSESSMENT.md).

The exports are provisional C-like reconstructions. Start with a small routine
and check its assembly, callers and referenced data before trusting its types
or meaning. `FUN_...` names are generated by Ghidra. `om3_...` labels below were
assigned from the pinned upstream research; they are not recovered vendor names.

## Main application landmarks

- [Defaults-table accessor](analysis/decompiled-main/functions/60405804.c): returns
  the table at 0x605f6d90. Its immediate and instruction boundaries were checked.
- [Settings getter](analysis/decompiled-main/functions/603f34ec.c): upstream landmark
  for investigating setting IDs and their storage.
- [COLOR1 settings](analysis/decompiled-main/functions/604037f9.c),
  [COLOR2](analysis/decompiled-main/functions/6040391a.c),
  [COLOR3](analysis/decompiled-main/functions/60403a3b.c) and
  [COLOR4](analysis/decompiled-main/functions/60403b5c.c).
- [COLOR builder](analysis/decompiled-main/functions/60518381.c) and
  [selector](analysis/decompiled-main/functions/60518573.c): a useful path into
  color-processing request construction. The selector's table reference and
  builder call match the known byte landmarks. Opaque `user_defined` operations
  and `in_A0`/`in_A1` inputs are unresolved semantics/ABI, not original C constructs.
- [Color register writer](analysis/decompiled-main/functions/604a3e73.c): upstream
  landmark for writes toward image-processing registers.
- [Section loader](analysis/decompiled-main/functions/60045ed5.c) and
  [section-end selector](analysis/decompiled-main/functions/60045e6c.c): upstream
  landmarks relevant to runtime section layout.
- [External-flash parser](analysis/decompiled-main/functions/601e75ba.c): an upstream
  landmark for camera/flash accessory communication, not storage flash memory.

The full code, assembly, call edges and failure records are linked from
[DECOMPILATION.md](DECOMPILATION.md). The defaults and setting-name bytes reproduced
locally are in `analysis/observations/summary.json`.

## Other processors and Linux

- [Secondary MCU reset handler](analysis/decompiled-scpu/functions/080253d8.c).
  Its image maps at 0x08000000, and the reset vector selects Thumb code at
  0x080253d8. This differs from the container's payload-address field.
- [Linux kernel C](analysis/decompiled-kernel/all-functions.c): names recovered
  from kallsyms, plus heuristic function discovery. The reconstructed ELF's
  startup symbol matches the raw kernel header's branch target.
- `analysis/decompiled-linux` has separate folders for every analyzed ELF.
  Camera-related filenames include `usr__bin__wifi_remocon`,
  `usr__bin__isc_olnet`, `usr__bin__blebridge`, `usr__bin__sccore`,
  `var__www__fcgi-bin__isc_cgi` and `var__www__fcgi-bin__isc_file`.
  Filenames suggest research topics; they are not proof of a runtime feature.
- `analysis/embedded/rootfs` contains regular filesystem files, including startup
  scripts and service configuration. Symlinks/device nodes were inventoried
  rather than created as host objects. No firmware program was executed.
  Eighteen case-distinct files live under `analysis/embedded/rootfs-case-sensitive`;
  `rootfs-inventory.json` maps their original paths. Path-hash-prefixed ELF exports
  and the linux-corrections Ghidra project are authoritative for those files.
  Directories containing SUPERSEDED.md are excluded from the validated index.

## Finding code

For each component, `functions.tsv` maps function address/name to its C file,
body size, decompile status, warning count and diagnostic. `calls.tsv` records
direct call edges. Indirect calls are not resolved exhaustively.
`bookmarks.tsv` preserves Ghidra's analysis warnings/errors.

For example, from this folder in PowerShell:

```powershell
rg '60518381' analysis/decompiled-main/calls.tsv
rg -n 'MODE_COLOR_CREATOR' analysis/decoded/strings.jsonl
rg -n 'request_getmysetdata|get_partialmysetdata' analysis/observations/oishare-description.xml
```

The first command locates calls involving the COLOR builder. A printable string
match alone does not establish executable code, a reachable handler or feature
support. Decompiler completion is not proof of correctness.
